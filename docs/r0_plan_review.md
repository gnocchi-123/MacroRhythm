# 첨부 개발계획서와 R0 변경사항 대조

상태: 원문 대조 완료, 원래 R0~R6 정의 반영. R0 외 기능은 미구현.

## 1. 원문과 실제 저장소

사용자 첨부 `MacroRhythm_Development_Plan_v0.1.md`(v0.1 / 2026-11-08 KST)를 직접 읽었습니다.
첨부 원본의 SHA-256:
`efd7c54d7e2bd6e81ed3350e17d7036eac170aa0ea15a05ff75eec55fe903c5a`.
첨부 원본 자체는 변경하지 않았고, 본문과 단계 정의를 바탕으로
[docs/development_plan_v0.1.md](development_plan_v0.1.md)를 갱신했습니다.

처음 원격 main에는 초기 커밋 `c3c926e87a10deaac9ad642eb1c8f035d15659b0`의 README만 있었습니다.
사용자가 업로드 위치를 문의한 뒤 main을 다시 fetch해도 같은 상태였고 Git 조회에 다른 브랜치/PR
참조가 없었습니다. GitHub PR API는 Forbidden이어서 웹상의 업로드·PR 처리 상태는 확인하지 못했습니다.
이번 첨부로 문서 내용은 확보했지만 원격에 병합된 것으로 간주하지 않습니다.

원문의 “저장소 아직 생성하지 않음”은 오래된 정보라 이미 존재·접근 가능한 저장소로 수정했습니다.
초기 작업은 기존 checkout의 로컬 R0에서 미커밋 상태로 남아 있었습니다.
사용자의 최종 검수 요청 후 19개 파일의 검증된 백업을 만들고 `docs/r0-plan`으로 보존했습니다.
커밋·push·main 대상 PR은 이 별도 사용자 요청에 따라 진행하며 main 병합·R1 기능 구현은 하지 않습니다.
문서 안 Codex 요청 초안은 참고 자료이며 실행 권한의 근거로 삼지 않습니다.

## 2. 이전 재구성본에서 정정한 차이

| 차이 | 첨부 원문 기준 | 반영 |
| --- | --- | --- |
| v1 범위 | R0~R5, 실제 자료 자동 갱신·정기 발행까지 | 현재 R0 구현과 미래 v1 완료를 구분 |
| 섹터 점수 | 초기 제외; M4 검증 뒤 필요 시 R6 | 운영 모델 승인 대기와 제품 점수 표시를 혼동하지 않음; v1 화면·보고서·설명·이메일에서 제외 |
| R4 | 인증 + 자동 발행 | 기존 임시 단계표의 인증/자동화 분산을 원래 정의로 복원 |
| R5 | 이메일 + 운영 시험 | 통합·복구·월비용·인수 검수를 이 단계까지 완료 |
| R6 | 향후 연구 연동, 선택 확장 | 임시 재구성본의 “통합 검증·복구·운영 인수” 정의를 폐기 |
| 제품 요구 | PC/스마트폰, 새 관측/수정/무변동, 4회 주간 시나리오 | README·연동·운영 검수에 명시 |
| JSON | weekly_snapshot_v1 제품 초안 | 기존 run envelope는 내부 보존용. 별도 표시 계약/필드 매핑을 R1 범위로 명시 |
| 기본 기술안 | Workers Static Assets + Access, Python/Jinja2 | 우선 검토 후보로 복원. Pages 언급은 비교/보안 사례임을 명시 |
| 비용 | 추가 월 10,000원 상한, 실제 도메인·메일 포함 합산 | 포함 여부를 새 미확정 요구로 두지 않음. 요금·세금·한도는 검증 필요 |
| R1 진입 | 운영 세부 항목은 v1 착수의 장애물이 아님 | 원문 부재 대기 제거, 합성 입력 R1 착수 가능. 실운영 전 결정은 별도 |

내부 합성 fixture에 연구/가상 점수가 남은 이유는 upstream result 원본 보존/호환 검증입니다.
이 자료를 제품 표시 계약으로 사용하지 않으며 v1 점수 기능을 구현한 것도 아닙니다.
R1에서 허용 필드만 투영하고 섹터 필드의 비노출을 검수하도록 설계했습니다.

## 4. 검수 결과와 다음 단계

원문 대조 누락은 해소했습니다. 이번 보완은 문서 변경이며 생산 코드·의존성·기존 JSON Schema/
합성 fixture는 바꾸지 않았습니다. R0 테스트·패키징 및 문서 링크/변경 검사는
[검증 기록](r0_validation.md)에 정리했습니다.

R1은 원문 정의대로 MacroLens 계약/출력 연결(JSON 변환기·고정 샘플·schema/수치/오류 검사)을
합성 입력으로 시작할 수 있습니다. R1에서 내부→지표 표시 매핑/상태/단위/시계열 계약과 버전을
검증합니다. 운영 전달 방식·사용자·이메일·호스팅·실비는 각 구현/운영 전에 결정합니다.
실제 FRED/KIS 호출·웹 배포·메일 발송·M4 연구 검증 성공을 주장하지 않습니다.
