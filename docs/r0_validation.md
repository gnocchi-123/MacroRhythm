# R0 검증 및 인수 기록

검토일: 2026-11-08 (Asia/Seoul). 초기 브랜치: 로컬 `R0`. 최종 검수/반영 브랜치: `docs/r0-plan`.

## 1. 구현한 기반

- Python src 패키지 `macrorhythm` 0.1.0. 버전 노출만 제공하며 런타임 외부 의존성 없음.
- `pyproject.toml`, Python 3.12 선택, `uv.lock`, pytest/Ruff 및 계약 검사용 개발 의존성.
- 문서·테스트 구조, 로컬 비밀/데이터/생성물 제외 규칙.
- 첨부 원문 개발계획 반영·대조, MacroLens 사실 조사·연동 계약·운영/보안/비용 설계.
- 원래 R0~R6 정의 복원, v1 섹터 점수 제외 및 weekly_snapshot_v1 표시 계약의 후속 매핑 설계.
- JSON Schema 초안과 원본 합성 실행에서 얻은 3개 계약 예제. exporter나 데이터 수신기는 미구현.

`.env`가 필요한 코드가 없어 `.env.example`은 만들지 않았습니다. 키/개인정보는 추가하지 않았습니다.
원래 개발계획서는 시작 시 로컬/원격 main에 없었으나 사용자가 원본 파일을 첨부해 대조를 완료했습니다.
[원문 검토 기록](r0_plan_review.md)에 실제 저장소와의 차이·이전 임시 단계표의 수정·반영 위치를 기록했습니다.
문서의 향후 실행 요청 초안은 참고로 구분하며 현재 R0 외 기능을 실행하지 않았습니다.

## 2. 실제 수행한 검증

환경: Linux, Python **3.12.14**, uv **0.13.5**. Python 3.13/3.14에서는 실행하지 않았습니다.
기본 uv 캐시 `/home/agent/.cache/uv`는 읽기 전용이어서 처음 잠금 명령이 실패했고,
`UV_CACHE_DIR=/tmp/macrorhythm-uv-cache`로 수정 후 성공했습니다. 검증 무력화는 하지 않았습니다.
캐시와 venv의 파일시스템 차이로 `UV_LINK_MODE=copy`를 사용합니다.

저장소 루트에서:

```bash
export UV_CACHE_DIR=/tmp/macrorhythm-uv-cache
export UV_LINK_MODE=copy
uv sync --locked
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
uv build
```

| 점검 | 실제 결과 |
| --- | --- |
| 잠금 생성·잠금 설치 | 성공, 저장소 `.venv` 생성 |
| pytest | **21 passed**, 실제 테스트 실행, skip/xfail 없음 |
| Ruff lint / format | 통과 |
| sdist → wheel 빌드 | `macrorhythm-0.1.0.tar.gz`, `macrorhythm-0.1.0-py3-none-any.whl` 생성 |
| 별도 `/tmp` 가상환경에 wheel 설치 | 의존성 없이 설치, 저장소 외부에서 `python -I` import 및 설치 metadata 버전 확인 성공 |
| Git 원격 읽기 | MacroRhythm main 조회·MacroLens main 참조 clone 성공 |
| MacroLens 소스/계수 보존 | 참조 체크아웃 `git status` 비어 있음, diff 없음, HEAD 변경 없음 |
| 제외 규칙 | `.env`, `.env.production`, local 사용자 파일·reports/artifacts/site·venv 제외 확인; `.env.example`과 합성 예제는 제외하지 않음 |

테스트 구성: 설치 패키지/metadata 버전 1개, schema 자체/예제 존재 1개, 실제 합성 예제 적합 3개,
잘못된 버전·형식·시각·상태·모드·모델 등에 대한 거부 13개, 필수 지표 누락 거부 1개,
보류 사유/빈 점수 확인 1개, upstream 추가 메타데이터 보존 1개 = 21개.

MacroLens 직접 확인은 임시 참조 checkout에 `PYTHONDONTWRITEBYTECODE=1`을 적용하고 출력은
별도 `/tmp`에 두었습니다. socket 연결과 FRED urlopen을 예외로 막은 상태에서 다음을 수행했습니다.

- research-v1 합성 완료: research_complete, 11개 섹터.
- 합성 자료의 INDPRO만 메모리상 제거: held, 점수 0개, 지표 누락 사유.
- demo-v1 합성 완료: demo_complete, 가상 3개 섹터.
- 각 저장 bundle에 원본 `load_run` 무결성 확인.

이 검증은 예제 생성과 R0 계약 설계의 근거입니다. MacroLens의 전체 테스트 suite,
실제 FRED 수집·KIS·이메일·접근 프록시·호스팅은 실행/검증하지 않았습니다.
원본 bundle은 `/tmp` 임시 자료로 프로젝트에 포함하지 않았으며 향후 지속 존재한다고 가정하지 않습니다.
프로젝트 테스트는 외부 checkout 없이 포함된 합성 예제로 실행합니다.

## 3. 문서·보안 검토

문서별 현재 구현/제안 상태, 필드명·상태·시점·변환을 확인한 MacroLens 코드와 대조했습니다.
문서의 로컬 Markdown 링크는 모두 유효했고 합성 예제의 credential 필드/이메일 주소 검사도 통과했습니다.
19개 변경 파일의 일반적인 토큰·개인키·이메일 패턴 검사에서 발견 사항이 없었습니다.
최종 파일 목록과 변경 공백은 `git status`, `git diff --check`로 확인했습니다.
이 점검은 전용 secret scanner나 배포 침투 검사를 대체하지 않습니다.

R0에 인증 기능은 없으므로 사이트를 공개할 수 있는 상태가 아닙니다. 운영 보안 검수 조건은
[운영 설계](architecture_operations.md)에 기록했습니다. 현재는 서버·배포·메일 워크플로가 없어
실수로 실데이터 API를 호출하거나 공개 발행하는 실행 경로도 추가하지 않았습니다.

## 4. 남은 결정과 제한

- 내부 교환 `0.1.0`과 제품 표시 weekly_snapshot_v1의 최종 매핑/버전, exporter 소유권, producer 고정 버전.
  R1에서 확정/검증. source 모델은 재현 계보용이며 섹터 점수 표시는 v1에서 제외.
- upstream은 독립 JSON Schema/export API를 제공하지 않음. 후속 어댑터의 의미·해시·전송 검증 필요.
- 전체 시계열/보고서 index 계약은 후속 설계. upstream 코드의 라이선스/배포 조건도 재사용 방식 확정 시 확인.
- 인증 사용자 규모/수단·origin 우회 차단·전달 저장처·보관/복구 정책·이메일 공급자 미정.
- 09:00 발행의 지연 허용/자료 cutoff/held 알림, 실비를 합산한 월 10,000원 이내 서비스 조합 미정.
- 최신 서비스 요금/무료 한도는 실계정에서 확인하지 않았으므로 월 10,000원 달성을 보장하지 않음.
- 실제 수집 성공, 운영 연동, 웹 배포, 정확한 정시 발행, 향후 새 클라우드 인스턴스 복원은 검증하지 않음.

## 5. R1 진입 판단

**원문 정의의 합성 자료 기반 R1 구현에 진입 가능**합니다. 원문 대조를 완료했고 패키징·오프라인
계약 검증 기반이 준비됐습니다. R1에서 지표 전용 변환기·표시 schema·고정 샘플을 구현하고
내부/표시 계약·단위·변경 상태·전달 책임을 확정/검증합니다. 운영 계정 부재로 독립 개발을 막지 않습니다.
실데이터/운영 단계의 준비 완료는 아닙니다. R1에서는 먼저 bundle 무결성/호환/오류 검증과
계약 의미 검사를 구현하고, MacroLens 계수·연구 코드의 변경은 R1 범위에도 포함하지 않습니다.

첨부 반영은 문서 보완이며 생산 코드·의존성·내부 schema·예제는 변경하지 않았습니다.
v1의 실제 갱신/화면/알림·4회 주간 시나리오는 후속 R1~R5에서 검수하며, R6는 M4 검증 후 선택 확장입니다.

초기 변경은 로컬 R0의 미커밋 파일로 남아 있었고 원격에는 main 초기 커밋만 있었습니다.
사용자의 최종 검수 요청에 따라 검증된 백업 후 `docs/r0-plan`으로 보존했습니다.
커밋·push·PR의 실제 결과와 커밋 ID/URL은 최종 보고에 기록합니다. main 병합·배포는 수행하지 않습니다.

**판정: R0 구현·설계 완료.** 실제 수집·화면·보고서·인증·예약 발행·이메일 기능은 추가하지 않았습니다.
MacroLens 원본/참조 소스와 M4 연구 코드는 수정하지 않았습니다.
합성 입력 기반 R1을 막는 미해결 구현 문제는 없습니다. R1에서 계약/매핑/전달 책임을 확정하며
실운영 전에는 인증·보관·공급자·비용과 데이터 이용 조건을 검증해야 합니다.

최종 검수에서는 잠금 설치/테스트/Ruff를 재실행하고, sdist에서 wheel을 빌드해 별도 환경에서 설치합니다.
후보 파일 19개와 기존 Git 이력에 비밀 파일 경로·일반적인 키/토큰/개인키·이메일·실제 주입된
credential의 일치 여부를 값 출력 없이 검사합니다. 이는 전용 secret scanner의 완전성 보장이 아닙니다.
