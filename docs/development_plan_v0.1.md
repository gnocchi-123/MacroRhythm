## 0. 의사결정 요약

**핵심 결정:** MacroLens를 투자 연구·공통 데이터 엔진으로 유지하고, MacroRhythm을 별도 저장소의 웹 서비스로 개발한다. MacroLens M4가 완성되기를 기다리지 않고 M1~M3의 안정적인 기능을 재사용한다.

| 항목 | 상태 | 내용 |

| 목적 | 확정 | 개인 투자 판단에 참고할 미국 거시경제 지표를 일정 주기로 정리·제공 |

## 1. 문제 정의와 성공 기준

### 1.1 해결하려는 문제

현재의 MacroLens는 정교한 데이터·분석 결과를 CLI 및 파일로 확인하는 연구 중심 도구다. 사용자가 투자 판단 전에 매주 거시경제 상황을 신속하게 확인하려면 별도의 읽기 쉬운 웹 화면, 정기 발행, 과거 비교 및 알림이 필요하다.

### 1.2 최종 사용자 경험

1. 월요일 오전 9시 KST에 최신 주간 보고서를 웹사이트에서 확인할 수 있다(인프라 지연 가능성은 명확히 공지).
2. 네 지표의 **최신 원자료 값**, 변환 지표, 관측일, 출처, 전주 대비 상태, 그래프를 확인한다.
3. 전주 대비 변화를 한국어 문장으로 읽고, 이전 주간 보고서를 선택해 비교한다.
4. 이메일에 포함된 보고서 링크로 로그인하여 웹·모바일에서 확인한다.
5. 새 경제지표 관측이 반영되지 않은 주에는 '새 관측값 반영 없음'이라고 표시한다. 공식 발표 여부가 확인된 경우에만 '신규 발표 없음'이라고 표현한다.
6. 수집·품질 검사에 문제가 생기면 숫자를 꾸며 내지 않고 '갱신 보류/일부 오류'를 표시한다.

### 1.3 v1 완료 기준(정량·검증 가능)

- 연속 **4회**의 주간 생성/발행 시나리오를 시험하고, 정상·실패·중복 실행의 결과를 기록한다. 실제 달력 기준으로 4주를 반드시 기다릴 필요 없이 과거/모의 실행으로 선시험 가능하다.
- 네 지표의 원자료·변환값이 기존 MacroLens와 표본 비교에서 일치한다.
- 각 지표에 관측일, 수집 시각, 데이터 출처, 단위, 정상/지연/보류 상태가 존재한다.
- PC 및 스마트폰 대표 화면 크기에서 핵심 정보를 무리 없이 읽을 수 있다.
- 허가받지 않은 사용자가 생산·미리보기 링크 및 데이터 파일에 접근하지 못함을 직접 테스트한다.
- 이메일 발송·중복 방지·실패 기록·재시도/수동 재발행을 테스트한다.
- 추가 고정 월비용을 1만 원 이하로 유지한다(도메인 구매, 유료 메일, 외부 서비스 이용료 발생 시 실제 합산 확인).

## 2. 데이터 범위와 표현 기준

| 분류 | FRED ID | 표시할 원자료 | 보조 지표/변화 | 유의점 |
|---|---|---|---|---|
| 성장 | `INDPRO` | 산업생산지수 | 전년 동월 대비 증가율(%) | 산업생산은 미국 경제 전체 GDP가 아님 |
| 고용 | `UNRATE` | 실업률(%) | 3개월 전 대비 변화(%p); MacroLens 연구 요인은 부호 반전 | 실업률의 수준과 개선/악화 방향을 따로 표시 |
| 물가 | `CPIAUCSL` | 소비자물가지수 | 전년 동월 대비 상승률(%) | CPI 수준과 물가상승률은 별개 |
| 금리 | `DGS10` | 미국 국채 10년 금리(%) | 28일 달력 기준 변화(%p) | 28거래일이 아니라 28달력일을 사용하는 기존 규칙 존중 |

- 원자료와 MacroLens의 표준화 요인을 혼동하지 않도록, 메인 카드에는 이해하기 쉬운 원자료 및 변환값을 우선 표시한다.
- 지표별 **관측 대상일** (`observation_date`), **가져온 시각** (`retrieved_at_utc`), **보고서 기준 시각** (`as_of_utc`), **실제 발행 시각** (`published_at_utc`)을 구분한다.
- 이번 주에 값이 바뀌었다고 곧바로 새 관측이 발표됐다고 판단하지 않는다. 이전 발표치의 수정/정정 여부를 따로 구분한다.
- 비교는 최소 **전주**, 이후 4주 전·13주 전을 선택적으로 도입한다. 같은 관측일의 수정과 새 관측일의 추가를 구별한다.
- 과거 보고서는 생성 당시 확정된 스냅샷을 보관한다. 지금의 최신 FRED 자료로 과거 보고서를 몰래 다시 쓰지 않는다.
- 현재 MacroLens 연구의 `strict_point_in_time=false` 한계를 존중하며, 보고서 이력을 엄밀한 과거 투자 시점 재현이라고 소개하지 않는다.
- 향후 ICSA, 근원 PCE, 2년물 금리 등의 추가는 별도 요구사항/데이터 계약 변경으로 관리한다.

## 3. 서비스 화면·정보구조

**A. 홈 대시보드 (`/`)**
- 상단: 보고서 기준 주, 마지막 정상 생성 시각, 상태 안내(최신/변경 없음/지연/오류).
- 본문: 성장·고용·물가·금리 4개 지표 카드. 각 카드에 최신값/단위/관측일/변화량/차트 이동.
- 하단: '이번 주 거시경제 변화 요약' 4~6문장 및 지표 출처/해설 한계.

**B. 지표 상세 (`/indicators/<id>`)**
- 시계열 그래프, 원자료·변환값 전환, 기간 선택(예: 1년/3년/5년), 자료 메타데이터, 과거 값 수정 알림.
- 모바일 터치 가독성과 그래프 대체 텍스트 확보.

**C. 주간 보고서 (`/reports/YYYY-MM-DD`)**
- 해당 주간 고정 스냅샷, 이전 보고서와 비교, 갱신/정정/오류 구분, 원자료 출처.
- 공유받은 이용자에게도 동일하게 보호된 웹 페이지 제공.

**D. 보고서 아카이브 (`/reports`)**
- 날짜별 보고서 검색 및 과거판 조회. 차후 CSV 다운로드는 라이선스와 접근권한 검토 후 추가.

**E. 운영자 상태 (`/status`)**
- 최근 수집, 검증, 발행 및 이메일 처리 상태. 공개 범위에서 제외하고 관리자만 접근하는 방법 검토.

> 화면 기준: 숫자만 강조하는 투자 추천 UI보다 **출처·관측일·비교 기준이 함께 드러나는 읽기 쉬운 정보 UI**를 우선한다.

## 4. 시스템 아키텍처

```text
FRED 공식 API
     |
     v
MacroLens (기존 저장소)
  ingest / snapshots / features / history
     |
     | versioned report JSON / validated snapshot
     v
MacroRhythm (별도 저장소)
  adapter -> schema 검증 -> 요약 템플릿
                |                  |
                v                  v
          HTML·차트 생성       이메일 내용 생성
                |                  |
                v                  v
      Cloudflare 정적 호스팅   이메일 발송 서비스
                |
                v
      Cloudflare Access: 초대된 이용자만 열람
```

### 4.1 책임의 경계

- **MacroLens**: FRED 수집, 원본 보존, 변환·검증, 데이터 시점 정책, 실행 이력과 분석값 산출, 향후 M4 섹터 투자 연구.
- **MacroRhythm**: 출력 형식 계약 검증, 대시보드, 한국어 설명 문장, 정기 실행 오케스트레이션, 접근 통제, 이메일 알림, 과거 보고서 UI.
- **금지**: MacroRhythm에서 INDPRO/UNRATE/CPIAUCSL/DGS10의 핵심 계산식을 별도로 다시 구현하여 두 결과가 갈라지게 만들지 않는다.
- **연동 원칙**: MacroLens의 공개된 안정 버전 또는 고정 커밋에서 생성한 스냅샷을 읽는다. M4 연구 브랜치를 운영 의존성으로 직접 끌어오지 않는다.
- **M4 독립성**: `feat/m4-kis-data`의 미병합 연구 코드는 건드리지 않으며, 대시보드 제작을 이유로 `main`에 합치지 않는다.

### 4.2 초기 기술 제안(확정 전 검수)

| 영역 | 기본 제안 | 선택 이유 / 조건 |
|---|---|---|
| 계산 | 기존 MacroLens Python / uv | 재사용 극대화, 추가 Python 재구현 최소화 |
| 내보내기 | 버전 관리된 JSON 스냅샷 | 프론트엔드와 계산 로직 결합 완화 |
| 보고서 생성 | Python + Jinja2 | 기존 사용자 개발 환경과 친숙, 정적 HTML 생성 |
| 차트 | 경량 JavaScript 차트 라이브러리 | PC·모바일 상호작용, 외부 호출 최소화 |
| 디자인 | 반응형 HTML/CSS | 초기에는 무거운 웹 프레임워크 불필요 |
| 배포 | **Cloudflare Workers Static Assets** 후보 | 정적 콘텐츠 서비스, 서버 상시 가동 필요 없음 |
| 접근 통제 | **Cloudflare Access** 후보 | 이메일 기반 허가자 목록으로 비공개·초대 공유 |
| 주간 실행 | GitHub Actions `schedule` + `workflow_dispatch` 후보 | 현재 GitHub 환경 활용 및 수동 재실행 제공 |
| 알림 | Resend 또는 동등 메일 서비스 후보 | API로 정기 발송 가능; 도메인 인증과 실제 무료 조건 확인 |
| 이력 | 실행별 변경 불가능한 JSON + 배포 산출물 | 고정 주간판 조회 및 재현 가능성 확보 |

**공식 확인 주의:** 원문은 Cloudflare Workers의 정적 자산 지원을 기술 제안의 근거로 삼았다. 이번 R0에서 최신 서비스 정책·요금은 재검증하지 않았다. Cloudflare Access 무료 한도는 소규모 사용자를 대상으로 제공하지만 실제 설정·접근 제어의 적용 범위를 테스트해야 한다. GitHub Actions의 예약 작업은 높은 부하 시 지연·누락 가능성이 있으므로 '정각 발행 보장' 수단으로 쓰지 않는다. 메일 API는 도메인 인증·발송 제한·운영 약관에 따라 추가 비용이 생길 수 있다.

## 5. 연동 데이터 계약(초안)

**산출물 제안**: `weekly_snapshot_v1.json`

**R0 실제 출력 검토:** 아래 JSON은 원문의 제품 표시용 초안이며 MacroLens가 현재 생성하는 파일이
아닙니다. 확인한 MacroLens main은 `result.json`의 정수 `schema_version=2`, `mode`,
`status=demo_complete/research_complete/held`, 지표별 `observation.retrieved_at` 등을 사용합니다.
`validation_status`에는 "미검증 연구용" 문구가 들어가므로 아래 complete/partial/held와 직접 연결할 수 없습니다.

R0의 [run envelope Schema](contracts/macrolens-run-0.1.0.schema.json)는 **내부 원본 교환 계약 `0.1.0`**입니다.
원본 result를 보존하며 점수도 포함할 수 있지만 사용자 표시용 산출물이 아닙니다.
`weekly_snapshot_v1`은 R1에서 별도로 정의/검증할 **지표 전용 표시 계약**입니다.
두 버전을 동일시하지 않으며 내부 result를 그대로 브라우저에 전달하지 않습니다.
필드·단위·시각·변경 상태 매핑과 남은 설계 범위는 [연동 설계](macrolens_integration.md)의
"원문 weekly_snapshot_v1과 내부 교환 계약의 관계" 절에 정리했습니다.<br>
**관리자 정보**: `schema_version`, `run_id`, `model_version`, `report_week_kst`, `as_of_utc`, `retrieved_at_utc`, `generated_at_utc`, `validation_status`, `source`, `indicators`, `comparison`, `summary_inputs`.

```json
{
  "schema_version": "1.0",
  "report_week_kst": "YYYY-MM-DD",
  "run_id": "<MacroLens run id>",
  "model_version": "<MacroLens model version>",
  "as_of_utc": "<ISO-8601 timestamp>",
  "generated_at_utc": "<ISO-8601 timestamp>",
  "validation_status": "complete | partial | held",
  "indicators": {
    "INDPRO": {
      "observation_date": "YYYY-MM-DD",
      "raw_value": null,
      "raw_unit": "index",
      "transformed_value": null,
      "transformed_unit": "pct_yoy",
      "previous_report_value": null,
      "update_kind": "new_observation | revision | unchanged | unavailable",
      "status": "ok | stale | held"
    }
  }
}
```

위 JSON은 **표본 규격**이지 실제 조회한 값이 아니다. `null`은 설계 예시로 사용했다. 실제 구현 시 각 지표의 단위와 금리의 `%p` 차이 표현을 별도로 선언하고, 모든 지표/시각 및 출처/오류 목록을 포함한다. 스키마 검증 실패 시 발행을 중단하거나 명시적 보류판을 발행한다. 중복 생성·동일 주차 재발행에는 수정 이력/버전 번호를 붙인다.

**계약 검증 항목**:
1. 기존 MacroLens 수치와 소수점 허용오차 내 일치.
2. 원자료 값과 변환값 단위·표시 이름이 뒤바뀌지 않음.
3. 지난 주 값과 이번 주 값의 차이가 계산과 일치.
4. 이미 생성된 실행 ID·주차의 중복 발송 방지.
5. 결측·지연·오류를 실제 최신값으로 오해하게 만들지 않음.
6. 스키마 주요 버전 변경 시 사전 호환성 테스트.

## 6. 자동 요약 작성 규칙

기본은 **AI API 없이 수치로 검증 가능한 결정론적 문장 템플릿**이다. 예를 들어:

- 성장: `INDPRO 전년동월대비 상승률은 {x}%이며, 직전 주간 보고서 대비 {delta}%p {상승/하락/변화 없음}했다.`
- 고용: `실업률은 {x}%로, 가장 최근 이용 가능한 관측일은 {date}이다.`
- 금리: `10년물 국채금리는 {x}%이며, 28일 전 기준 {delta}%p 차이를 보였다.`
- 신규 발표가 없으면 `이번 주에는 새 월별 관측값이 반영되지 않았다.`라고 표시.
- 부적합/누락 자료가 있으면 추론·분석 문장을 만들어 내지 않고 상태와 원인을 설명.

`긍정/부정`, `매수/매도`, `침체 확정`처럼 실증 근거가 필요한 단정과 예측을 쓰지 않는다. AI 문장 생성은 후속 기능으로 두되, 도입한다면 계산 결과를 읽기 쉬운 문장으로만 재작성하고 숫자 변경·근거 없는 전망 생성 금지, 원본 템플릿과 대조 검수, 별도 요금 승인 필요.

## 7. 발행·알림·장애 대응

### 7.1 시간 운영

- **목표 공개 시간**: 매주 월요일 09:00 KST. 시각·주차 규칙을 `Asia/Seoul`로 고정한다.
- 첫 구현에서는 자동 예약 실행을 주차별 1회 수행하되 수동 실행과 실패 재시도 경로를 별도로 둔다.
- GitHub Actions 예약 작업은 지연/누락 가능하므로 실제 발행 시각을 기록하고, 정각 준수는 별도의 보장 대상으로 오해하지 않는다.
- 필요 시 수집·검증을 사전 실행한 뒤 월요일 09시 전후 발행 단계로 분리하되, 데이터가 주차 기준 시각 이전에 이용 가능했는지 확인한다.
- **발행 전 검사 실패**: 오래된 정상 스냅샷을 새 보고서로 바꿔치기하지 않는다. 이전판은 보존하고 사용자에게 갱신 보류 상태를 표시한다.

### 7.2 이메일

- 먼저 **승인받은 수신자에게 한정**해 발송. 수신자 관리, 주소 검증, 등록/해지 절차, 동의 확인 필요.
- 제목 예시: `[MacroRhythm] 2026-11-09 주간 거시경제 보고서` (날짜는 예시).
- 메일은 제목·핵심 요약·보호된 대시보드 링크만 담는다. 접근 제한을 우회할 수 있는 내부 파일이나 인증 토큰은 포함하지 않는다.
- `report_week_kst` + 보고서 버전을 기준으로 중복 발송 방지. 실패 기록과 운영자 재발송 수단 제공.
- 메일 발송용 별도 DNS/도메인 또는 발송 도메인 검증 비용이 발생할 수 있으므로 공급자 가입 전 승인.

### 7.3 접근 통제와 보안

- 초대 이메일 허용 목록 기반. 운영자와 조회 전용 이용자를 분리한다.
- 원본 FRED 키, KIS 키(초기 미사용), 배포 토큰, 메일 API 키는 저장소나 생성 HTML에 두지 않고 비밀 변수로만 보관한다.
- 생산 도메인뿐 아니라 `pages.dev` 또는 `workers.dev`, 미리보기 배포, 정적 JSON 자산 URL을 모두 접근통제 시험 대상으로 둔다.
- URL을 안다고 들어올 수 있는 공개 미리보기 경로가 남지 않도록 실제 로그인되지 않은 브라우저로 검증한다.
- 운영 로그에 토큰·개인 이메일·민감 키가 남지 않게 하고, 비밀값 유출 대비 회전 절차를 기록한다.
- 외부 데이터 재배포 약관을 준수한다. 초기 지표는 FRED 출처·저작권/제공자 약관을 검토하고, KIS 수집 가격 자료는 검토 없이 웹에 게시하지 않는다.

## 8. 마일스톤과 브랜치

MacroLens의 `M0~M4`와 혼동하지 않도록 MacroRhythm 단계는 **R0~R6**로 표기한다. 기간은 계획 검토·개발 범위 추정용으로도 약속하지 않는다.

| 단계 | 산출물 | 완료 판정 | 저장소/브랜치 예시 |
|---|---|---|---|
| **R0** 요구사항·기본 구조 고정 | `docs/development_plan_v0.1.md`, README, 구현 선택 기록 | 확정/제안 분리, 데이터 경계 합의 | MacroRhythm: `docs/r0-plan` |
| **R1** MacroLens 계약/출력 연결 | JSON 변환기, 샘플 스냅샷, 스키마 테스트 | MacroLens 계산 결과와 일치, 실패 처리 통과 | `feat/r1-macrolens-adapter` |
| **R2** 화면·그래프 | 홈/상세/아카이브 정적 사이트 | 모바일/PC, 단위/관측일 확인 | `feat/r2-dashboard-ui` |
| **R3** 설명·보고서 보관 | 규칙 기반 요약·주간 고정 보고서 | 전주 비교, 보류·수정 구분 및 저장 | `feat/r3-reporting` |
| **R4** 인증·자동 발행 | 접근 통제, 예약 실행, 실패 대응 | 비인가 접근 차단, 재시도/중복 없음 | `feat/r4-publish-access` |
| **R5** 이메일·운영 시험 | 알림·상태점검·운영 매뉴얼 | 허가된 수신자 발송, 결측·장애 시험, 월비용 확인 | `feat/r5-ops-email` |
| **R6** 향후 연구 연동(옵션) | M4 결과 카드/섹터 점수 | M4 검증 결과와 연구상태/한계 표시 | 추후 별도 결정 |

- 각 단계: 구현 → 자동 테스트 → 샘플·실제 입력 검수 → PR → 사용자 승인 → `main` 병합.
- 이번 R0와 후속 웹 연동에서는 기존 MacroLens의 동결 계수·과거 재현·M4 연구 로직을 변경하지 않는다.
- 초기 구현 브랜치는 로컬 `R0`였으며, 사용자의 최종 검수 요청에 따라 변경사항을 보존하고
  `docs/r0-plan`에서 커밋·push·main 대상 PR을 준비한다. main 병합은 사용자 검토 후 별도 진행한다.
- R4에서 인증과 자동 발행을 함께 검수하고, R5에서 이메일·운영 시험 및 v1 인수를 완료한다.
  복구·통합 검수를 R6로 미루지 않는다. R6는 M4 검증 후 별도 승인한 선택 기능이다.
- MacroLens에서 꼭 필요한 내보내기 기능은 작은 독립 PR로 제안하고, 기존 결과 JSON을 변환하는 어댑터로 해결할 수 있으면 별도 수정 없이 진행한다.
- **R0~R5가 v1 범위**, R6는 별도 승인 확장. M4가 미완성이어도 R0~R5 완료 가능.
